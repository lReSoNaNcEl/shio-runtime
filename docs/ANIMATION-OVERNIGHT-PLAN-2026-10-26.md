## Architecture Review

Следуем Body Animation Domain и planned phase forecasting в `ARCHITECTURE.md`. Main — один generator и валидированный transport; Avatar Runtime — единственный body/hand composition; AudioPlayer — consumed PCM; Mixer — лицо; Overlay — consumer. API HTTP contract и модель/asset caches не меняются. Изолированный тестовый профиль не подменяет пользовательские настройки. Данные для проверки поз вычисляются transient; сохраняются изображения и bounded geometric aggregates, не raw poses в Runtime diagnostics.

## Подтверждённые причины и вопросы

1. На каждой phase transition очередь сбрасывается, а следующий phase request ждёт уже выполняющуюся предыдущую генерацию. На старте PCM дополнительно инвалидируется work. Это последовательная задержка поверх shared-GPU latency.
2. Добавлен regression с 500 ms stroke generation и двухсекундной подготовкой до PCM: текущий код выдаёт `ARDY_AUDIBLE_UNDERRUN`. Он подтверждает, что окно для заблаговременной подготовки сейчас не используется.
3. Прежняя проверка hand score измеряла углы локальных bones, но не высоту/положение wrist, palm facing или геометрию кончиков пальцев. Кадр kiss всё ещё не доказывает подход к губам. Требуются фактические rig-space измерения.
4. Совместный run зависел от Cloudflare и озвучивал rate-limit fallback. Нужны раздельные результаты Character qualification и реальных Fish/ARDY components; synthetic или fallback речь не объявляется Character pass.
