# Техническое задание на эксперимент ARDY и Fish Audio S2 Pro

Статус: ТЗ для реализации. Дата: 26 октября 2026 года.

Создать экспериментальную ветку Shio с полностью генерируемой анимацией тела
VRM-персонажа через NVIDIA ARDY и потоковой озвучкой через Fish Audio S2 Pro.
Удалить библиотеку `.vrma` и F5-TTS из исполняемой конфигурации проекта.
Сохранить существующие механики лица, глаз, взгляда, моргания, LipSync и
вторичного движения. Синхронизировать тело, речевые эмоции и артикуляцию с
фактически воспроизводимым PCM, а не со временем получения текста.

Подтверждённое значение «PCE» из исходного запроса — **PCM-стриминг**.
ТЗ не является отчётом о готовой реализации или пройденной GPU-квалификации.

## 2 Обязательный результат

1. Обычный диалог использует реальный ARDY для движения тела и реальный
   Fish S2 Pro для голоса. Движения строятся при работе приложения.
2. В исходниках, установочном пакете и ресурсах новой сборки нет `.vrma`.
   Нет скрытого скачивания прежних клипов или замены их заранее записанными
   GLB, BVH, NPZ либо массивами кадров.
3. В исполняемом коде, зависимостях, конфигурации, установке и активных UI
   отсутствует F5-TTS. Нет запасного F5-движка и фиктивной успешной озвучки.
4. Приложение остаётся Electron + React + Three.js + VRM, включая Overlay.
5. Речь начинается до завершения всего ответа; анимация не требует сначала
   синтезировать весь ответ в WAV или сгенерировать всю сцену целиком.
6. Лицо, глаза и LipSync работают при диалоге, остановке, смене модели и в Overlay.
7. Страница `http://localhost:8000` полностью описывает и тестирует новый Fish
   pipeline, сохраняя действующие ASR-функции.
8. Документация, установка, диагностика, тесты и упаковка соответствуют новой
   конфигурации. Завершение подтверждается статическими и живыми проверками.

ARDY — обязательный генератор тела. CaMN и EMAGE в эту работу не входят.
Процедурная безопасная поза допускается для запуска, перехода и явного отказа
генератора. Она не подменяет ARDY в штатных диалогах.

## 3 Архитектурные границы

Канонический источник — `ARCHITECTURE.md`, прежде всего главы 15, 16 и 20.

| Область | Ответственность |
| --- | --- |
| Character Response Generation | Реплика, семантическая эмоция, намерение подачи и жеста |
| Conversation Admission | Единственная точка допуска очередного диалога |
| Conversation Runtime | Жизненный цикл одного допущенного turn и завершение cleanup |
| Speech Runtime | Подготовка текста, синтез, поток и делегирование воспроизведения |
| AudioPlayer | Единственный владелец воспроизведения и позиции PCM |
| API на 8000 | ASR, Fish inference, подготовка голосовых референсов |
| Avatar Runtime | Выбор визуального воплощения, ретаргетинг, смешивание и применение к VRM |
| AvatarExpressionMixer | Единственная финальная запись facial expressions |
| Overlay | Потребитель проекции того же воплощения |

Интеграцию ARDY оформить как Main-owned Adapter и внутреннюю службу приложения
за публичным контрактом Avatar Runtime. Вынесенный Python inference worker
является механизмом Adapter, не новым владельцем поведения и не Speech Runtime.
Не помещать ARDY в speech API и не переносить мутации модели в Electron Main.
Worker не получает полномочий управлять Electron, файлами пользователя или UI.

Предлагаемое расположение worker и его изолированного окружения — под
`apps/desktop/motion/`; окончательный путь закрепить архитектурным решением.
Desktop не импортирует реализацию `apps/api` и не использует её `.venv` как
неявную зависимость. Команды установки обоих приложений остаются независимыми.

Main владеет запуском и отменой ARDY, параметрами процесса, окружением,
вычислительными лимитами и проверкой результатов. Avatar Runtime в renderer
остаётся владельцем композиции и финального применения костей.
В Overlay не запускать второй ARDY и не добавлять ему привилегированный preload.

Character State не хранит кадры, траектории, PCM, очереди генератора и будущие
delivery cues. Речевая подача не перезаписывает разговорную эмоцию Character State.
LLM передаёт смысловые намерения, не кости, координаты или команды модели.

Анимация и речь остаются воплощением персонажа; для них не создавать Tool Actions.
Владение Action Runtime, Permission Guard, инструментами, Memory, Goals,
Browser Control и Project Awareness не изменять.

## 7 Динамическое тело через ARDY

В штатном режиме ARDY генерирует короткий горизонт движения с продолжением
из текущей истории. Не перезапускать персонажа из bind pose на каждой фразе,
эмоции или пакете PCM. Очередь и горизонт ограничены временем и числом кадров.

Нужны смысловые профили как минимум для спокойного объяснения, согласия,
несогласия, вопроса, удивления, смущения, радости, поддержки, размышления,
приветствия, покоя и слушания. Длительное бездействие продолжает двигаться
без повторного запуска диалога или самостоятельного выбора новой эмоции.

Персонаж остаётся на месте в обычной беседе. Перемещение root, сидение,
полноэкранное действие и танец доступны только соответствующему выбранному
профилю. Portrait/Bust ограничивают амплитуду и положение рук.
Сохранить различие обычного разговорного жеста и выраженной реакции.

LLM семантически выбирает intent. Adapter переводит типизированный intent
в ограниченное описание движения и constraints. Не вводить обработчик
ключевых слов русской реплики, который сам выбирает жесты.

Ретаргетинг должен явно учитывать skeleton ID/version, порядок суставов,
исходную позу, локальные и мировые вращения, оси, единицы, масштаб и VRM 0/1.
Нормализовать quaternions, контролировать конечность чисел и диапазоны.
Маска головы/шеи сохраняет полномочия Gaze/Head Motion; глаза, челюсть,
мимика и visemes не принимаются от ARDY как скрытые каналы.

Проверить руки у лица, плечи, локти, кисти, таз и контакт стоп; исключить
систематические проникновения рук в тело и резкие скачки. Качество пальцев
оценить отдельно для выбранного checkpoint; не заявлять отсутствующие степени
свободы как результат генерации. Сглаживание не должно разрушать смысловой жест.

При смене VRM инвалидировать все результаты старого скелета. При опоздании
движения не проигрывать его ускоренно задним числом. Использовать ограниченное
продолжение или плавный безопасный возврат с явным статусом degraded.
Такой возврат не должен возрождать библиотеку заранее записанных анимаций.

## 8 Полная замена F5 на Fish S2 Pro

В `apps/api` перенести или реализовать реальный Fish Adapter и один
принадлежащий сервису inference worker. Сохранить ASR на faster-whisper/Silero.
Fish владеет голосом, а не VRM-состоянием или воспроизведением.

Удалить F5 engine, специфические маршруты, request/response-поля, заголовки,
fallback, прогрев, конфигурацию `F5_*`, зависимости, prefetch и release asset
правила. Vocos, RuAccent и связанные пакеты удалять после проверки, что они
не нужны новой конфигурации. Нельзя удалить ASR вместе с TTS-зависимостями.

Проверить голосовой реестр: логические voice IDs и исходные референсы
сохранить, если они совместимы. Подготовка Fish conditioning — отдельный
производный кеш, привязанный к checksum референсов и revision модели.
Исходные `reference.wav` и `reference.txt` не перезаписывать. Доступность голоса
означает наличие валидных ресурсов и успешную подготовку нового движка.

Один нормальный turn использует одну логическую text-in/audio-out сессию.
Не оставлять старые два F5 synthesis workers и WAV reorder buffer как второй
путь озвучки. Ограничить число Fish-сессий; конфликт получает типизированный
busy-результат. Новую сессию нельзя запустить поверх незавершённой отмены старой.

При переносе имеющегося incremental decoder проверить его зависимость от
upstream signature, монотонность PCM-суффиксов и качество стыков. Флаг upstream
`streaming` сам по себе не доказывает раннюю выдачу аудио. Отдельно проверить
первый пакет до окончания входного текста и воспроизведение до конца synthesis.

Отмена должна прекращать реальную GPU-работу. Если нужен перезапуск worker,
использовать детерминированное завершение и честные `loading`/`warming`/`ready`.
Не называть последующую загрузку мгновенным восстановлением и не скрывать её.

## 9 API и потоковые контракты

Порт API остаётся `8000`. `SHIO_SPEECH_API_URL` по-прежнему Main-owned,
не редактируется renderer и меняется только после перезапуска Desktop.

За основу взять Fish-ветку, но версии утвердить по фактической совместимости.
При изменении семантики или схемы повысить соответствующую версию, не переиспользуя
тот же номер для несовместимого протокола.

| Интерфейс | Обязательное поведение |
| --- | --- |
| `GET /health` | Реальный статус ASR/Fish, warmup, модель/revision, версия контракта и bounded failure |
| `GET /voices` | Fish-совместимые logical voices, готовность references и conditioning |
| `GET /emotions` | Канонические cues и версия эмоционального контракта |
| `POST /tts/warmup` | Идемпотентная подготовка выбранного голоса тем же engine |
| `WS /tts/stream` | Версионированный text-in, delivery-in, PCM-out и управление отменой |
| `/recognize`, `/ws/asr` | Сохранение согласованного ASR-контракта |
| `/voices/status`, `/voices/sync` | Сохранение validated single-flight atomic sync |
| Старый `/synthesize` | Удаление; старый клиент получает явную несовместимость без скрытого F5 |

Для WebSocket сохранить типизированные сообщения `start`, `text`, `delivery`,
`finish-input`, `audio-ack`, `cancel`; ответы `ready`, `audio`, `complete`,
`cancelled`, `error`. `finish-input` завершает вход, но не запрещает отмену
при продолжающемся synthesis/playback. `complete` API не означает, что
AudioPlayer уже закончил звучание.

`ready` объявляет sample rate, channels и sample format. Базовый переносимый
профиль Fish-ветки — mono Float32 LE PCM 44,1 кГц; клиент не должен ошибочно
воспроизводить его как PCM16, 24 кГц или частоту AudioContext.

В контракте зафиксировать идентификаторы turn/session, монотонные sequence,
число samples, связь с text/delivery segment и максимальные размеры сообщений.
Для надёжной синхронизации добавить или однозначно вывести cumulative sample
offset каждого audio-пакета. Metadata и бинарный payload сопоставляются строго;
неполная пара и несовпадение длины являются ошибкой протокола.

На всех очередях нужны реальные лимиты и backpressure. ACK означает
согласованное принятие/освобождение транспортного кредита, не факт звучания.
Позицию воспроизведения получать отдельно от AudioPlayer.
Проверять дубликаты, пропуски, обратный порядок, неверную версию, превышение
лимита, stalled consumer, disconnect и timeout.

Все IPC авторизуют sender, валидируют аргументы и входят в canonical inventory.
Не принимать пути к Python, checkpoint, файлам или исполняемому коду из renderer.
Новый транспорт для движения — узкий типизированный Main-owned интерфейс,
а не generic invoke, произвольный HTTP endpoint или полный dump процесса.

## 10 Новый System Prompt и эмоциональный контракт

Переработать речевые инструкции Character Prompt, Response Policy,
Character Request Composer и safe incremental filter как один согласованный
pipeline. Сохранить личность Shio, Tool Requirement/Plan, границы authority,
Memory/Goals и bounded allocation секций prompt. Не добавлять ARDY/Fish
инструкции в каждый tool payload или полный список профилей в каждый запрос.

Единый versioned emotion contract должен связывать:

- каноническую семантическую эмоцию и интенсивность;
- голосовую подачу: style, pace, energy, volume;
- Fish rendering tags;
- существующий VRM facial profile и допустимый body intent;
- область действия cue и его привязку к текстовому сегменту.

За основу можно взять `contracts/emotions.v2.json` и генерацию manifests из
Fish-ветки. Удалить зависимости от S22 и сопоставить cues текущим VRM-механикам.
Выходные manifests не должны редактироваться независимо друг от друга.
Отсутствующую VRM expression отображать через существующий совместимый профиль,
не записывая произвольный morph из LLM. Не ограничивать новую подачу F5-списком
эмоций, но держать semantic IDs и поля runtime-валидируемыми.

Fish S2 использует **квадратные** `[tag]`, например `[excited]` и `[whisper]`.
Круглые скобки S1 не считать новым протоколом S2. Провайдер допускает описательную
подачу; отделить её от канонической эмоции, тела и видимого текста.

Предлагаемый LLM-контракт — совместимое с Fish-веткой разделение:

```text
[happy][voice:bright playful tone]Привет! Рада тебя видеть.
[whisper][voice:whisper in small voice]А теперь маленький секрет.
```

Это внутренние маркеры Shio. Они преобразуются в typed delivery intent;
только Fish Adapter рендерит финальные provider tags. `[voice:...]` не должен
попасть в Fish буквально. Описание ограничено 120 символами и не содержит
вложенных скобок, angle brackets, управляющих символов или команд другим системам.
Сохранить поддержку оттенков подачи; не заменять её одним списком эмоций.

Принять конечный grammar отдельным контрактом. Потоковый parser должен
переживать разрез любого маркера между чанками, незакрытый тег, malformed JSON,
Markdown-ссылки, code spans и обычные скобки в пользовательском тексте.
Нельзя просто вырезать любые квадратные скобки регулярным выражением.
Untrusted Browser/Project/Web evidence не может создавать delivery authority.

Разделять исходный ответ, видимый текст, речевой текст, нормализованный речевой
текст и typed cues. Служебные маркеры не появляются в чате, субтитрах,
истории/Memory и произносимом тексте. Tool-call-first round не выдаёт речь.
Подача меняется по смысловым границам; лимит сегментов объявить явно и проверить.

## 11 Общая временная шкала речи и тела

Главные часы диалогового воплощения — фактически потреблённая аудиопозиция
AudioPlayer/AudioWorklet. Полезно объявить её как исходный PCM sample offset
с явным преобразованием при resampling, а не как число render frames или
samples устройства без известной частоты.

Для каждого turn нужны связанные turn ID, speech session ID, motion session ID,
generation epoch, segment/cue IDs и model generation. Аудио содержит диапазоны
samples; динамическое движение — timestamps относительно согласованной timeline.
Cue меняет голосовую проекцию, выражение и body intent на границе звучания,
не сразу после чтения маркера из LLM. Разговорная эмоция остаётся за её владельцем.

Схема потока:

```text
Character LLM → safe protocol filter → текст + typed delivery/body intent
  текст + delivery → Speech Runtime → Fish API → PCM → AudioPlayer
  body intent → Avatar public contract → Main ARDY Adapter → motion chunks
AudioPlayer playback position → Avatar composition → тело + лицо + LipSync
  composed presentation → Overlay
```

Начинать подготовку движения до playback по ограниченному доступному контексту.
Оценённая длительность текста может использоваться только для предварительного
планирования; затем корректировать незапущенный горизонт по реальному PCM.
Не переписывать уже проигранные samples и уже показанную позу.

На старте ждать только ограниченный минимальный запас PCM/движения. Политика
deadline должна быть явной. При недоступном ARDY речь может продолжиться с
безопасной позой и видимым degraded status; такой сценарий не засчитывается
как успешная квалификация ARDY.

Во время audio underrun или pause разговорный motion cursor не убегает вперёд;
допустимы только ограниченные idle/breathing contributions. На resume продолжить
согласованное время без скачка и ускоренного проигрывания накопившихся жестов.
Без озвучки использовать локальные монотонные часы Avatar Runtime.

Не обещать точное совпадение жеста с отдельным словом без word/phoneme alignment.
Базовая цель — синхронизация смыслового сегмента, начала/конца речи и смены
подачи. ARDY сам по себе не выдаёт акустические timestamps.

## 12 Сохранение лица глаз и LipSync

Сохранить AvatarExpressionMixer, facial profiles, моргание, speaking-eye
поведение, gaze arbitration, Head Motion, viseme blending, закрытие рта,
phrase envelopes, уши, хвост и VRM spring bones там, где они доступны модели.
Не заменять их S22-логикой и не удалять из-за отсутствия VRMA.

LipSync читает фактически воспроизводимый PCM через существующий анализатор
или эквивалентный проверенный источник AudioPlayer. Учитывать 44,1 кГц,
resampling, паузы, тишину, смех/вдохи, законченный поток и cancel.
Полученный, но ещё не звучащий пакет не открывает рот заранее.
Не выдавать amplitude-driven visemes за phoneme alignment.

Нормализованные body bones, маска шеи/головы, facial mixer и secondary motion
композируются в определённом порядке ровно один раз за кадр. Нет competing
last-writer-wins и накопления quaternion offsets от кадра к кадру.

Overlay отображает ту же временную позицию тела, cues и итоговые mouth weights.
Независимая случайная генерация анимации в Overlay запрещена.
Проверить скрытие/возврат главного окна, открытие/закрытие Overlay и модель reload.

## 13 Отмена ресурсы и диагностика

Отмена turn инвалидирует epoch, upstream LLM, Fish, ARDY, PCM-очередь,
motion-очередь, pending cues и LipSync. Поздний пакет старого turn/session/model
не меняет новый аватар и не начинает воспроизведение.
После завершения cleanup можно допустить следующий turn.

Все owned processes, listeners, timers, MessagePorts, Workers и media resources
имеют идемпотентный teardown. App exit, renderer crash и model replacement
не оставляют inference child processes или зависшие аппаратные ресурсы.
Environment subprocess явный и credential-minimal; не использовать `npx`.

Диагностика показывает реальные состояния Fish и ARDY, источник текущего
движения, warmup, версии, глубину очередей, playback offset, возраст cue,
ошибку синхронизации, dropped/stale chunks, cancellation/recovery time и
реальный degraded режим. Runtime Health не выводится из соседних UI-проекций.
Сохранять существующие debug-сценарии, заменив obsolete показатели новыми.

В диагностике не хранить raw PCM, массивы скелета, reference transcripts,
prompt/reply, provider secrets и полные worker outputs. Артефакты тестов
могут содержать явно подготовленные тестовые реплики и тестовые записи;
они игнорируются Git и не становятся conversational Memory.

Не копировать ограничения облачного API как свойства локального Adapter.

Нужны:

  фрагментов/пакетов и раздельные времена первого PCM и первого звучания.

не требуется. Граница приложения должна быть отражена в правилах UI.

| Область | Обязательные проверки |

## 17 Живая квалификация

Для реализации запрошена полноценная live-проверка; одна сборка не является
приёмкой. После изменения Main/preload/renderer пересобрать и перезапустить
Electron. Использовать собранный renderer и emitted assets, а не изолированный
раннер, который случайно обходит реальную упаковку.

Матрица сценариев:

1. Холодный старт, загрузка VRM, прогрев Fish/ARDY и первый ответ без A-pose.
2. Короткий и длинный русский ответ, английский ответ, technical text и числа.
3. Нейтральная речь, радость, спокойная поддержка, удивление, смущение и шёпот.
4. Внутренняя смена подачи в одной реплике, смех/вздох, пауза и возвращение к речи.
5. Продолжение ввода текста после первого PCM; голос и тело стартуют до конца ответа.
6. Остановка до первого аудио, в середине речи и после finish-input; немедленный
   новый turn без старых звуков, cues и движений.
7. Медленный consumer, underrun, ARDY deadline miss, disconnect и ошибки workers.
8. Idle/listening/thinking/greeting, длительное бездействие и возврат в разговор.
9. Полный рост, Bust и Portrait; руки, плечи, стопы, голова, взгляд и secondary motion.
10. Debug Preview генерируемого движения, reroll, transitions и diagnostics.
11. Overlay вместе с главным окном, обе темы, скрытие окна и повторное открытие.
12. Смена VRM, повторный dispose, renderer restart, app exit и отсутствие сиротских workers.
13. Страница на 8000: голоса, delivery, реальный streaming, cancel и рабочий ASR.
14. Чистая установка экспериментального пакета, repair/doctor и повторный запуск.

Сохранить короткие записи или кадры, bounded telemetry и таблицу pass/fail
по каждому сценарию. Тесты провайдера и performance измеряют реальные модели,
не mock. Не отмечать непроверенный сценарий как пройденный.

## 18 Метрики и критерии качества

Измерять cold и warm отдельно. Указать baseline Fish без ARDY и совместный
профиль Fish + ARDY + ASR + Electron/VRM. Привести median/p95 по не менее
20 warm ответам и отдельный непрерывный прогон не менее 30 минут.

| Показатель | Требование |
| --- | --- |
| Streaming | Первый PCM и первое звучание происходят до завершения полного ответа |
| Совместная скорость | На целевом профиле после прогрева нет устойчивого роста очередей или OOM |
| Cue timing | Ошибка применения cue относительно доступной PCM-границы p95 не более 100 мс |
| Остановка локального output | После принятия cancel новые звук/движение прекращаются не позднее 200 мс; аппаратный audio tail учитывается отдельно |
| Late output | Ни один пакет invalidated epoch не применяется после cancel/model switch |
| Render | Цель 60 FPS; фактические frame time median/p95 и dropped frames фиксируются |
| Ресурсы | Peak VRAM/RAM, warmup, worker reload и teardown измерены для полной связки |
| Стабильность | 30 минут диалогов, idle, отмен и Overlay без утечки очередей/processes и нарастающего drift |

Числа 100/200 мс и 60 FPS — критерии этого эксперимента, не заявленные
гарантии NVIDIA/Fish. Отдельно измерять отмену GPU-работы и время повторной
готовности: быстрое локальное mute не доказывает остановку inference.
Если критерий не достигнут, он остаётся непройденным; изменение порога оформлять
явно, а не подгонять после измерения. Речевые word-level ошибки не смешивать
с cue timing, для которого есть известная граница samples.

Качество пластики оценивать на целевом VTuber: уместность жестов, читаемость
в камере, плавность, отсутствие проникновений/скачков и сохранность выражений.
Женская VRM сама по себе не задаёт стиль движения. Закрепить профиль Shio
с ограничениями осанки, амплитуды и выразительности; seed нужен для воспроизведения.
