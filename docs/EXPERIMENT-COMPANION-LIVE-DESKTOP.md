# Живая трансляция Шио

## Цель и приёмка

Ветка `codex/desktop-companion-v1`. Пользователь начинает сеанс на рабочем столе, видит, какое окно транслируется, может перебить Шио голосом и остановить захват за одно действие. Эмоция и жест следуют произошедшему событию. Обычная работа за компьютером может проходить в тишине.

| Сценарий | Критерий |
|---|---|
| Старт и завершение | Видны выбор источника, состояние подключения, активный микрофон, предпросмотр, остановка и сбой. Индикация соответствует живому сеансу при переходе между вкладками. |
| Новый чат | С первого экрана доступны разговор и начало совместного просмотра. Список инструментов отражает доступные возможности. Основное действие помещается в узком окне. |
| Avatar Preview | Удобно выбрать и воспроизвести доступное движение, увидеть текущее состояние и вернуть модель в обычную позу. Проверить русскую и английскую локали, светлую и тёмную темы. |
| Реакция персонажа | Взгляд и артикуляция согласованы с вниманием и звучащей речью. У дерзкой и спокойной реплики различается подача. Главный аватар и Overlay получают одну скомпонованную позу. |
| Инициатива браузера | Пользователь может указать HTTPS-ссылку на страницу для сверки. По смыслу события Шио один раз за сеанс может открыть страницу в собственном Chrome. Следующий комментарий учитывает только подтверждённый результат. Остановка, смена политики или начало речи отменяют ожидающую работу. |
| Инструменты в разговоре | Во время трансляции явная просьба об операции с браузером или терминалом проходит через существующие плагины, Action Runtime, Permission Guard и проверку результата. Содержание кадра и системная речь не задают команды. |
| Задержка | Обычная голосовая просьба описать кадр получает короткий путь без повторного решения той же моделью. Сравнить число запросов и время до текста на Codex CLI, `gpt-6-luna`, effort `low`. Проверки контрактов остаются воспроизводимыми с фиксированными ответами. |

## Архитектура

Main владеет временем жизни сеанса и областью разрешённой сверки. Источник разрешения на действие — выбор пользователя или его явная реплика. Обнаружение события и выбор момента принадлежат существующему циклу наблюдения. Микрофон, очередь речи и выдача хода остаются у Speech Input и Conversation Admission. Все внешние операции выполняют действующие адаптеры. UI читает проекции этих владельцев. Для проверки используются изолированные профили и тестовые страницы.

Решение принимает модель по словам пользователя и двум признакам недавнего разговора. Изображение и экранный текст поступают отдельно при подготовке содержательного ответа.

Первая приёмка прошла на 998 тестах Desktop и 66 тестах API. После перезапуска рабочего API проверены распознавание русского вопроса по HTTP, четыре финальные фразы через WebSocket и реальный поток Fish с ранним PCM, подтверждениями и завершением. В проверке потока на прогретом сервере первые данные пришли за 249 мс.

Для повторения проверок модели из `apps/desktop` доступны `npm run qualify:watch`, `npm run qualify:watch:autonomous` и `npm run qualify:speech-motion -- --codex-luna-low`. Квалификаторы Node используют прокси из окружения, Electron также разрешает системный прокси. Полный детерминированный набор тестов запускается из корня через `npm run desktop:test:regression` и `npm run api:test`.

Проверку трёх голосовых вопросов повторяет команда `npm run qualify:watch:voice` из `apps/desktop`. Нужны Windows, собранный клиент, запущенный API с готовым ASR и вход в Codex CLI. Windows System.Speech создаёт тестовую WAV на месте из четырёх фраз. Требуется установленный русский голос рабочего стола, например Microsoft Irina Desktop. Команда показывает только тестовое окно Spaces, подаёт запись вместо микрофона и проверяет три расшифровки, их появление в чате и три ответа по содержимому окна. На итоговой сборке получены четыре финальные расшифровки и три ответа с деталями страницы Spaces. После проверки временный профиль удаляется.

## Читаемость страницы в трансляции

При вопросе о странице приложение раньше уменьшало весь рабочий стол до 768×432. На широком мониторе текст карточек и адрес Chrome теряли детали. Первое испытание на одиночном кадре 3414×1292 показало, что даже при полном разрешении модель может спутать соседние буквы V и W.

Для каждого голосового или текстового обращения Desktop берёт свежий кадр выбранного источника с его пропорциями. Захват ограничен 3840 пикселями по стороне, 8,29 мегапикселями и 3 МиБ JPEG. Для кадров от 2000 пикселей по длинной стороне Main готовит обзор и до шести перекрывающихся фрагментов исходного масштаба. При превышении общего бюджета 4 МиБ модель получает исходный JPEG. Автономное наблюдение использует прежнюю пару компактных кадров.

Проверка `npm --prefix apps/desktop run qualify:watch:voice -- --read-text --wide` открывает Chrome с временным профилем. Вопрос передаётся текстом через чат, когда работает трансляция. На видеопотоке 3414×1292 модель Codex CLI `gpt-6-luna`, усилие `low`, точно воспроизвела видимые хост, путь и случайный фрагмент адреса, затем два независимых кода шрифтом 14 CSS-пикселей. После прокрутки в отдельном ответе точно прочитала четвёртый код, который до этого находился за нижним краем. Значения каждый раз генерируются заново и отсутствуют в вопросах и названии окна.

Трансляция показывает текущую видимую область. У скрытой адресной строки, сокращённого URL и содержимого ниже края окна нет соответствующих пикселей в кадре. Самостоятельная проверка страницы в браузере Шио остаётся отдельной возможностью.

## Задержка голосовых ответов 26 ноября

В рабочем сеансе с 12:54 до 13:00 МСК сопоставлены шесть решений `addressed` с последующими запросами Шио. Начало и конец запроса связаны по `traceId`. Начало решения об обращении вычислено по времени записи `microphone disposition` и её `elapsedMs`. Все шесть ходов завершились прямым ответом на Codex CLI, `gpt-6-luna`, `low`. Каждый ответ использовал четыре изображения, вызовов инструментов не было. Для расчёта использованы метаданные.

| Интервал | Медиана | Диапазон |
|---|---:|---:|
| Проверка, обращается ли пользователь к Шио, после готовой расшифровки | 5,05 с | 4,43–6,19 с |
| От результата проверки до старта запроса ответа, включая подготовку кадра | 0,16 с | 0,13–1,59 с |
| Запрос к модели с кадром до получения готового текста | 8,49 с | 6,11–12,58 с |
| От начала проверки обращения до готового текста | 15,21 с | 10,80–17,61 с |

Среднее по шести полным интервалам — 14,80 с. Адаптер Codex CLI получает текст после завершения дочернего процесса. В текущем пути озвучка может начаться только после получения этого текста. Точное время от конца речи пользователя до первого звука Шио для этих ходов в журнале Main отсутствует. Метка `input_received` начинается уже внутри обработки запроса к модели. В отдельной сохранённой проверке на прогретом Fish от запроса синтеза до первого PCM прошло 304 мс.

Для проверки ускорения стоит сопоставлять время от физического конца фразы до первого воспроизведённого сэмпла, долю ответов на мысли вслух и точность чтения мелких надписей. Для широкого экрана локальная подготовка обзора и трёх фрагментов на синтетическом кадре 3414×1292 заняла 59 мс по медиане 15 прогретых запусков. Время передачи изображений и обработки на стороне модели входит в отдельный запрос ответа.

В отдельном опыте сравнили последовательное и одновременное выполнение тех же двух запросов к Luna Low. Три вопроса относились к разным случайным кодам на одном подготовленном кадре 3414×1292. Для каждого вопроса выполнили оба варианта, меняя порядок между парами. В параллельном варианте ответ готовился без инструментов и оставался внутри теста до решения об обращении.

| Что попросили прочитать | Последовательно | Параллельно |
|---|---:|---:|
| Фрагмент видимого адреса | 23,55 с | 11,36 с |
| Код слева вверху | 25,87 с | 12,18 с |
| Код справа внизу | 26,92 с | 13,28 с |

Все шесть результатов содержали правильный код. Медиана ожидания в этом опыте снизилась с 25,87 до 12,18 с. Эти абсолютные значения относятся к другому времени и тестовому контексту. Опыт показывает, что транспорт способен исполнять два запроса одновременно. До внедрения нужны проверки отмены, нагрузки, речи в сторону, перебивания и запросов инструментов. При неподтверждённом обращении ответ должен отбрасываться до чата, озвучки и записи в историю. Опыт не менял поведение клиента.
