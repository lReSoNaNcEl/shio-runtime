# Реплики Шио в трансляции и проверка YouTube

## Architecture Review

Watch Together анализирует кадры и звук выбранного источника в пределах действующего разрешения. Electron Main проверяет выбор модели и хранит до шести озвученных реплик в пределах сеанса. Допуск реплик использует действующий путь Attention, Proactive Initiative Gate и Conversation Admission. Остановка очищает контекст сеанса.

Для проверки встроенного плеера используется отдельный Chrome и локальная тестовая страница на loopback. Контрольный сервер закрывается вместе с проверкой. Производственный Watch Together продолжает наблюдать выбранное окно по действующему разрешению.

## Что изменено

- Модель выбирает тему наблюдения. Состояние плеера и неясные кадры пропускаются до допуска реплики и добавления заметки в контекст следующих моментов.
- Модель видит последние озвученные строки и может предложить две формулировки одной шутки. Runtime проверяет первые два слова и отдельные междометия. При совпадении он берёт подходящую вторую формулировку. Прерванные и не начавшиеся реплики не занимают место в истории.
- Инструкции для реплик ставят в приоритет видимую деталь из видео, свежую фразу, комическое сравнение и развитие предыдущей шутки. Мат остаётся частью стиля.

## Root Cause

Прежний контекст содержал одну последнюю реплику, а проверка отсекала только точное совпадение всей строки. Модель регулярно повторяла «Ну всё» и «Ебать» при новом продолжении. Состояние окна и содержимое проигрываемого ролика имели общий путь к комментариям.

Обычная страница YouTube воспроизвела сбой в отдельном Chrome без Electron. Часть запросов видеопотока завершалась `net::ERR_CONNECTION_CLOSED`, после чего плеер сбрасывал позицию и буфер. Ручное переключение на 360p воспроизвело тот же сбой. Официальный встроенный плеер прошёл контрольные 80 секунд без перезагрузки.

## Почему фикс работает

Проверка области наблюдения отсекает сбои плеера до озвучки и исключает их из контекста следующих реплик. Проверка начала применяется к уже произнесённым репликам после очистки управляющего протокола. Обе формулировки приходят в одном запросе модели.

## Файлы

- `WatchTogetherService.ts` и `watch-together.test.ts` содержат изменение поведения и регрессии.
- `qualifications/watch-together/playback.cjs` запускает официальный встроенный плеер для выбранного видео.

## Проверки

```powershell
npm run build
node apps/desktop/qualifications/watch-together/playback.cjs --dark --youtube-embed=Pq8pVWSeGGg
```

- Первые 5:00 ролика прошли через официальный встроенный плеер с нулём сбоев и перезагрузок. Шио начала 10 голосовых реплик с разными началами, девять завершились. Последняя началась около 4:56 и звучала при остановке проверки. Микрофон не запрашивался.
- Детали дошли во всех 39 наблюдениях. Модель отнесла четыре наблюдения к состоянию плеера, и Watch Together пропустил их до озвучки. При отдельной проверке модель увидела искусственный экран ошибки со старой расшифровкой, вернула `playback-status`, и озвучка не запускалась.
- Прошли 64 профильных теста, сборка, TypeScript, Biome, форматирование и импорты.
- Команда с `--smoke` прошла 15 секунд на финальной версии тестового запуска. Переходов страницы и возобновлений внутри плеера не было.

## Ограничения

Бесперебойное воспроизведение подтверждено для встроенного плеера в тестовом Chrome. Обычная страница YouTube в контрольном запуске по-прежнему сбрасывала воспроизведение примерно через 45 секунд. В семи из десяти озвученных реплик осталось повторение слова «блядь» внутри фразы.
