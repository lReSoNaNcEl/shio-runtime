# FlashMotion в Windows-пакете

## Architecture Review

Electron Main владеет процессом FlashMotion и проверяет протокол. Лаунчер готовит зависимости, CUDA-расширения и проверенные модели в отдельном окружении WSL2. Avatar Runtime применяет позу. AudioPlayer остаётся владельцем воспроизведения и позиции прочитанных сэмплов. Контракт Speech API сохраняется.

## Что изменено

- ZIP содержит worker, протокол, каталог и скрипты подготовки FlashMotion. Установка и диагностика доступны через штатный Windows-лаунчер.
- Инструкции Alpha описывают подготовку Ubuntu WSL2 и CUDA 12.8, первый запуск и восстановление повреждённых файлов.
- Каноническая архитектура закрепляет FlashMotion как генератор движений в основной ветке.

## Root Cause

Worker FlashMotion и его зависимости отсутствовали в Windows-архиве. Лаунчер требовал удалённые файлы ARDY и прерывал запуск до открытия Desktop. После исправления состава архива проявился второй блокер. Electron Builder пропускал обязательные peer-зависимости Desktop Control, и Main завершался с `ERR_MODULE_NOT_FOUND`.

## Почему фикс работает

Electron Builder помещает Python-файлы вне ASAR в структуру, доступную WSL. Лаунчер и Electron используют один каталог моделей. Подготовка проверяет закреплённые ревизии и контрольные суммы. Диагностика проверяет существующий нормализатор и веса в офлайн-режиме. Требуемые версии peer-зависимостей закреплены явно. Проверка ZIP проходит по графу упакованных зависимостей.

## Проверки

Прошли сборка ZIP, проверка 926 зависимостей, TypeScript, Biome, 939 тестов Desktop, 64 теста API и 31 тест Python-протокола и входов FlashMotion. В новой Ubuntu WSL2 на RTX 5090 собраны CUDA-расширения и пересчитан нормализатор S2G с совпавшим SHA-256.

Лаунчер установил Speech Pack и прошёл офлайн-диагностику. После готовности API он запустил Desktop из распакованного ZIP и остановил свой API после закрытия окна. Fish передал 413 696 сэмплов и начал отдавать PCM до `finish-input`. Whisper распознал тестовую аудиозапись, синтезированную Fish.

В отдельном запуске тот же Desktop подготовил оба кеша T2M из скачанных весов. FlashMotion перешёл в `ready`, а жест из каталога был виден в Preview и Overlay. Первый прогон подготовки ограничивался тестовым тайм-аутом. Повторный прогон завершился с лимитом, близким к штатным десяти минутам.

## Ограничения

Проверка выполнена на существующей Windows 11 с новой Ubuntu WSL2 и отдельными каталогами приложения. Включение WSL2 и установка NVIDIA-драйвера считаются системными предусловиями. На этой машине поддержка длинных путей Windows выключена. Изолированный Speech Pack установлен в короткий каталог после ошибки `MAX_PATH` в первом тестовом пути. Для запуска использован тестовый порт 18080, так как 8000 был занят другим процессом. Реальный синтез с распознаванием и проверка жеста выполнены в двух прогонах.
