# Автономные комментарии в «Трансляции»

## Поведение

Обычный запуск «Трансляции» разрешает Шио самостоятельно смотреть и комментировать выбранный источник. Микрофон по умолчанию выключен. Пользователь может включить его в диалоге выбора источника для голосового разговора и прерывания комментариев. Текстовое обращение получает актуальный кадр и без микрофона.

При выборе окна Шио получает звук процесса, которому принадлежит окно, и его дочерних процессов. Это включает другие вкладки и окна того же процесса браузера. При выборе монитора используется общий звук Windows с исключением Шио через `restrictOwnAudio`. Если звук окна недоступен, трансляция продолжает показывать это окно и сообщает о состоянии звука. Выбор окна не включает общий звук системы.

Фоновые наблюдения содержат обзор до и после изменения, при необходимости промежуточный кадр, и детальный фрагмент из исходного кадра размером до 960×960. Временные метки кадров и реплик источника используют общую шкалу. Модель получает частичные и завершённые фразы, уровни звука и спектрограмму. Изображения и звук хранятся только во временных буферах сеанса.

Речь источника и смена кадра допускают продолжение анализа. Для озвучки можно подождать паузу до 1,2 секунды, пока реплика актуальна. Разрешена одна активная реплика Шио. После завершённой озвучки действует интервал в девять секунд и ограничение до четырёх реплик за скользящую минуту. Модель может промолчать, если у неё нет конкретной реакции.

## Architecture Review

Electron Main подтверждает выбранный источник по текущему списку окон, привязывает звук к разрешённому источнику, валидирует объём и время наблюдений и отзывает разрешение при остановке. Адаптер Windows определяет PID только из разрешённого системного дескриптора. Пауза, приватность и отключение автономности сохраняют приоритет. Озвучка использует существующие Attention, Proactive Initiative Gate и Conversation Admission. Speech Input Runtime владеет микрофоном при его включении, AudioPlayer владеет воспроизведением. Desktop использует существующий HTTP/WebSocket-контракт Speech API.

## Проверка

Из корня репозитория после `npm run build`:

```powershell
node apps/desktop/qualifications/watch-together/playback.cjs --dark
node apps/desktop/qualifications/watch-together/playback.cjs --fixture
```

Обе команды запускают изолированный профиль Electron и отдельное окно Chrome. Первая использует ролик с Дахаком, вторая — локальную гонку со сценарными поворотами и русской озвучкой. Для локального сценария нужен установленный голос Windows на русском. Команды проверяют реальный захват, распознавание, начало и завершение озвучки в AudioPlayer и отсутствие запроса на микрофон.

- Локальная гонка прошла 5:00. AudioPlayer начал и завершил семь самостоятельных комментариев. ASR выдал 23 завершённых сегмента, два из них во время озвучки Шио. Запросов микрофона было ноль. Размер полученного кадра предпросмотра — 1984×1242. Среди комментариев были точные реакции и ошибки в интерпретации отдельных исходов гонки.
- YouTube в двух попытках сбросил воспроизведение примерно через 50 секунд. В тёмной теме до сброса AudioPlayer завершил один комментарий, а ASR выдал сегмент во время его озвучки. Ошибка плеера `Something went wrong. Refresh or try again later.` воспроизвелась в отдельном Chrome без Electron. Пять минут непрерывного воспроизведения YouTube не подтверждены.
- Все 1078 регрессионных тестов Desktop прошли. Проверки типов, форматирования, импортов и сборка прошли. Biome сообщил о десяти предупреждениях в остальных частях Desktop.
- На итоговой сборке дополнительно прошёл 15-секундный smoke в тёмной теме. Захват окна и распознавание запустились без запроса микрофона, остановка через интерфейс завершила сеанс.
