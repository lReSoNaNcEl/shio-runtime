# Качество движения и синхронизация речи — 27 октября 2026

Статус продолжения: **реализация WI2–WI5 завершена; визуальную приёмку пользователь выполняет самостоятельно**. По последнему указанию пользователя новые визуальные и Electron qualification-прогоны не выполнялись. Сборка и детерминированные проверки не доказывают художественную естественность. Исторические live-результаты ниже сохранены как baseline, а не как подтверждение финальной версии.

## Architecture Review

Границы не менялись: Avatar Runtime владеет визуальной композицией, AudioPlayer — часами потреблённого PCM, Fish — синтезом, Expression Mixer — финальными facial values, Overlay потребляет композицию. Character State, Event Bus, HTTP-контракт, модель SOMA и физические ограничения не менялись. Изменения не противоречат Runtime Boundaries, Core Architectural Invariants и Architecture Compliance Checklist.

## Причины и изменения

- При двух старых горизонтах в очереди forecast мог быть объявлен до фактического запроса. Детерминированное воспроизведение показало запланированную границу 72 и ошибочный повторный запрос с кадра 120. Теперь forecast объявляется только когда можно начать запрос, а необходимые для перехода кадры сохраняются. Это устраняет подтверждённый дефект очереди; живые samples сами по себе не доказывают, что он был единственной причиной каждого наблюдавшегося deadline.
- Кивки во время речи ранее определялись таймером без данных звука. Существующий Head Motion Runtime получает нормализованную сглаженную энергию LipSync; кивок требует активности, повторного снижения энергии и cooldown 2,8–5,2 с. После окончания речи и при новом сеансе старое значение не используется. Семантические жесты не выбираются аудиоэнергией.
- Добавлена опциональная запись Overlay для существующего qualification runner. Видео не содержит звук и имеет частоту 10 кадров/с; фактическая длительность может отличаться от времени записи, поэтому timing оценивается по диагностике, а не по шкале видео.

## Исторические проверки первого этапа

Прошли build, TypeScript, Biome check/format/imports, motion catalog, 46 motion Python tests и focused tests очереди и головы. Предыдущий полный Desktop regression прошёл 531 тест. Последний полный запуск после финальных изменений: 530 passed, два Browser Control fixtures failed (timeout и `COMPUTER_USE_FAILED` вместо ожидаемой ошибки); при отдельных последовательных повторах оба прошли. Поэтому последний полный regression не считается успешным. Во время работы тесты параллельно перемещались другими изменениями в рабочем дереве; эти изменения сохранены.

Не подтверждены: отдельный 60-секундный idle, короткая реплика до 3 с, полноценная длинная Character-реплика, стабильность всех переходов и нескольких последовательных ответов, совпадение акцента с нужным участком речи, выраженность новых кивков на слуховом A/B и художественная естественность. Проверка замены VRM сохранила LipSync после reload, но речь была fallback провайдера и не квалифицирует длинный Character-сценарий. Снятые видео без звука и с непостоянной временной шкалой недостаточны для окончательной приёмки. Установленный checkpoint: `ARDY-SOMA-RP-30FPS-Horizon60`, revision `244215084b22fcd29ab743017330e87411fe168a`.

## Root Cause (если был баг)

1. Очистка по концу PCM проверяла только текущий `context.speechBound`, пропуская ожидающие жесты за обычным presence. Также ожидался ранее опубликованный ненулевой clock.
2. Время ожидания свободного тела и первого horizon не входило в отсчёт подготовки: её локальные часы начинались позже фактической речи. Не было отдельной проверки свежести акцента по consumed samples.
3. Scheduler расходовал long-reply opportunity и cooldown только после успешного выбора. Отклонённая/повторная попытка повторялась на каждом кадре; воспроизведение дало более 1000 попыток за 30 секунд.
4. `BreathController.remove()` обнулял значение, использованное одновременно как состояние сглаживания. После каждого снятия добавлялся лишь первый шаг envelope, поэтому величина дыхания зависела от FPS и подавлялась.
5. Head authority наследовала ограничения полных body clips, хотя текущая ARDY mask исключает head/neck. Head generator сохранял незавершённый кивок при detach/attach.
6. Обычный пропуск/завершение подготовки попадал в общий catch контроллера анимаций, помечал профиль неисправным и запускал error fallback. Теперь три точных исхода (`ARDY_SPEECH_WINDOW_MISSED`, `ARDY_SPEECH_ENDED`, `ARDY_superseded`) не являются неисправностью профиля. Настоящие ошибки генератора по-прежнему остаются ошибками.

## Почему фикс работает

Очередь, физические фазы, речь и процедурная композиция сохраняют своих владельцев. Подготовка проверяется по тому же AudioPlayer source cursor, включая ожидание до её запуска; буферизация не тратит это окно. Существующий recovery освобождает позу, а очередь продолжает следующее выбранное движение только после его завершения. Снятие процедурного вклада теперь отделено от состояния генератора. Лимиты суставов, collision protection, standing constraints, SOMA checkpoint, Fish и HTTP-контракт не ослаблялись и не менялись.

## Ограничения

Визуальные, live Electron и новые Fish+ARDY прогоны по последнему указанию не выполнялись. Детерминированные тесты подтверждают механизмы, а не субъективную естественность или совпадение с конкретным словом. Новых измерений inference/p95 нет; историческую разницу выше нельзя приписывать финальным исправлениям. `/health` после продолжения сообщил `ready: true`, реальный Fish и ASR готовы. Исторические `FishReloadFailed` и отказ Character provider не получили доказанной воспроизводимой причины в этом продолжении; изменение их pipeline без доказательств не выполнялось. Наличие готового API не объявляется доказательством устранения всех возможных provider-сбоев.
