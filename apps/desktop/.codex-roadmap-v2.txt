Shio Vtuber Roadmap v2
Avatar Runtime, Observability, Gesture Scheduler и Passive Companion Mode
Назначение документа. Зафиксировать текущее состояние проекта Shio Vtuber и согласованный ближайший roadmap разработки. Документ предназначен для Codex / GPT-5.5 и должен использоваться как план последовательной реализации Work Items без крупных незапрошенных рефакторингов.
0. Правила выполнения для Codex / GPT-5.5
Выполнять строго один Work Item за один запуск модели.
После завершения Work Item проверить компиляцию, типы и запуск приложения.
Не переходить к следующему Work Item автоматически.
Не менять python-speech, Groq prompt, TTS backend, overlay-архитектуру и AvatarController без явной необходимости текущего Work Item.
Не выполнять большой несвязанный рефакторинг.
Если обнаружена архитектурная проблема вне текущего этапа, зафиксировать TODO или предложение, но не чинить её в рамках текущего Work Item.
Сохранять существующее поведение, если оно явно не указано как требующее изменения.

Work Item 5 — Passive Companion Mode
Цель. Добавить режим, в котором Shio постоянно слышит пользователя при включённой записи/стриме и сама решает, когда отвечать, когда молчать, а когда реагировать только невербально.
Ключевая идея. Это не YouTube integration. Shio не обязана подключаться к YouTube API. Она слушает локальный микрофон/ASR и работает как пассивный компаньон во время записи или стрима.
Always-on ASR
↓
RuleGate
├── obvious ignore      → stop
├── obvious nonverbal   → Avatar Runtime
├── obvious reply       → Shio LLM
└── uncertain           → Groq Llama 3.1 8B classifier
                              ↓
                        ignore / reply / nonverbal
                              ↓
                        Shio LLM only if reply
                              ↓
                            TTS
                              ↓
                        Avatar Runtime
5.1 RuleGate
RuleGate должен обрабатывать очевидные случаи без LLM и возвращать одно из решений:
type RuleGateDecision =
  | { type: "ignore"; reason: string }
  | { type: "reply"; reason: string; style?: string; emotion?: string }
  | { type: "nonverbal"; reason: string; emotion?: string; gesture?: string }
  | { type: "uncertain"; reason: string };
Obvious Reply
Пользователь явно обращается к Shio по имени.
Пользователь задаёт короткий прямой вопрос Shio.
Пользователь просит мнение.
Фразы вида: “Shio, что думаешь?”, “Сио, скажи”, “Фрирен, как тебе?”.
Obvious Ignore
Шум или мусор ASR.
Слишком короткая бессмысленная фраза.
Длинный монолог или рассуждение вслух.
Shio уже говорит.
TTS ещё не завершился.
Недавно уже был самостоятельный ответ.
Фраза похожа на технический мусор или обрывок.
Obvious Nonverbal
Пользователь смеётся.
Пользователь удивлён.
Короткая эмоциональная реакция не требует голосового ответа.
Подходящие примеры: “ахах”, “ого”, “мда”, “ну дела”, “капец”.
5.2 Llama 8B Reaction Classifier
Использование. Groq Llama 3.1 8B Instant используется только в редких неопределённых кейсах. Не отправлять каждую ASR-фразу в classifier.
Классификатор не генерирует реплику Shio. Он выбирает только действие: ignore, reply или nonverbal.
{
  "decision": "ignore | reply | nonverbal",
  "style": "short | joke | tease | support | curious | none",
  "emotion": "neutral | happy | curious | surprised | playful | annoyed",
  "confidence": 0.0,
  "reason": "short explanation"
}
Если classifier выбрал reply — только тогда вызывать основную LLM Shio.
Если classifier выбрал nonverbal — не вызывать Shio LLM, сразу отправить событие в Avatar Runtime.
Если classifier выбрал ignore — не делать ничего, кроме обновления recentUserUtterances.
Shio LLM должна генерировать только финальную реплику, а не решать каждую входящую фразу.

5.4 Настройки UI
Passive Companion Mode: on/off.
Reaction Frequency: low / medium / high.
Use Llama 8B classifier for uncertain cases: on/off.
Minimum seconds between autonomous replies: 8–15.
Interrupt user: never / only direct mention / allowed. По умолчанию — never.
Значения по умолчанию:
Passive Companion Mode = off
Reaction Frequency = low
Use Llama 8B classifier = on
Minimum seconds between autonomous replies = 12
Interrupt user = never
5.5 Ограничения Passive Companion Mode
Не использовать classifier для каждой фразы.
Не заставлять Shio LLM самой решать, отвечать или нет.
Не генерировать текст ответа в classifier.
Не вызывать TTS без решения reply.
Не перебивать пользователя без явного обращения.
Не отвечать слишком часто.
Не делать полноценный Behavior Tree на первом этапе.
Behavior Tree можно рассмотреть позже, если RuleGate + Reaction Router перестанут справляться.

5. Пока не делать без отдельного согласования
Audio Viseme Recognition — извлечение визем из готового аудио вместо текущего lipsync.
Любой крупный рефактор python-speech, выходящий за рамки текущих задач.
Пояснение. Face Tracking, MediaPipe, Webcam и ML Gesture System не включаются в roadmap, потому что проект принципиально не развивается в сторону управления аватаром через камеру или нейросетевой генерации жестов.
6. Критерии готовности ближайшего этапа
Debug Panel показывает ключевые состояния Avatar Runtime в реальном времени.
Runtime Timeline / Event Inspector помогает понять цепочку событий.
Test Full Runtime проходит полный цикл без ручной сборки сценария.
Gesture Scheduler запускает жесты поверх базовых состояний без конфликтов.
Idle Behaviors добавляют живость, но не выглядят навязчиво.
Passive Companion Mode не отвечает на каждую фразу пользователя.
В неопределённых случаях RuleGate использует Groq Llama 3.1 8B classifier.
Основная LLM Shio вызывается только когда принято решение reply.
Проект компилируется и запускается после каждого Work Item.
